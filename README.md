# HistChess: Legal counterfactual chess histories

**Status:** CPU-friendly research prototype. This is new code populating the supplied repository scaffold; the uploaded ZIP had empty scripts and data. No scientific results are claimed until the pipeline runs.

## Eight reproducible evaluations

1. Replay each full history with `python-chess`, recompute rule labels and independently validate all records.
2. A strictly board-only majority baseline (balanced-pair 50% accuracy by construction).
3. Canonical full-FEN feature oracle, correctly unable to see repetition occurrence history.
4. GRU prediction accuracy versus number of visible recent UCI moves, plus suffix discriminability.
5. Strict joint counterfactual paired accuracy for every baseline/model.
6. Exact ID / board / FEN / full-history cross-split leakage audit and 4-ply-prefix overlap warning.
7. A trained small token-GRU with CPU PyTorch, saving checkpoints and validation curve.
8. Two real pretrained open-weight LLM evaluations, one Hugging Face download at a time, on a **small balanced diagnostic subset** by default.

The generated dataset has four binary tasks: white-kingside castling *rights* (not immediate move legality), *legal* en passant, halfmove clock >=2, and current-position repetition >=3 (not prospective threefold draw claims). All moves start from the chess initial position. No model is allowed to see the true FEN in its history-only prompt (a full FEN would leak three of the four labels).

Pairs in each family share the exact visible board and turn. Castling, en passant and halfmove pairs differ in precisely one of the canonical six FEN fields. Repetition pairs have identical full canonical FENs but different occurrences. All labels are replayed using `python-chess`. `certificate` contains a replayable full move list and evidence fields, not a formally machine-checked proof system independent of python-chess.

**Limitations:** Synthetic templates share many prefixes; the split is group-disjoint by board, not independently generated by real human games. The small two-LLM sample is for pipeline verification, not statistical claims. Larger evaluations and an independent chess rules oracle should be added before journal submission. Using canonical `board.fen(en_passant='legal')` is intentional; python-chess calls `fen(en_passant='fen')` for a different FEN policy. Threefold `is_repetition(3)` is distinct from `can_claim_threefold_repetition()`.

## Kaggle usage

Create Kaggle Notebook -> Settings -> Internet **ON** and Accelerator **None** (CPU). Add the supplied patch ZIP as a Kaggle input Dataset or commit its files to your GitHub repository. Paste the provided `KAGGLE_ONE_CELL.py` into a single Python cell. The cell finds the patch ZIP, runs offline-free self-tests, trains the GRU, downloads two compact LLMs and archives outputs. The full data generation requires no Lichess download.

## Local / terminal

```bash
python -m pip install -r requirements.txt
python scripts/selftest.py
python scripts/run_all_kaggle.py --out histchess_results --pairs-per-task 80 --epochs 3 --llm-pairs-per-task 2 --strict
```

Use `--skip-llm` for a quick **incomplete** classical-only smoke run. Both model weights must download for all 8 categories to be complete. Increase to `--pairs-per-task 500 --llm-pairs-per-task 20` for a more informative (slower) run only after checking the smaller run.

## Output

`histchess_results.zip` includes `data/pairs.jsonl`, `validation.json`, `leakage_audit.json`, `baseline_metrics.csv`, `gru_metrics.csv`, `gru_learning_curve.csv`, `history_ablation.csv`, `llm_predictions.csv`, `llm_metrics.csv`, `run_status.json`, `manifest.json` and `tiny_gru_model.pt`. Large pretrained weights are **not** copied into output. `run_status.json` reports failures and indicates whether ALL required experiments passed.

An LLM download failure will **not** be passed off as an evaluated model. Use `--strict` so a failure stops the notebook with an error; partial output will still be zipped.
